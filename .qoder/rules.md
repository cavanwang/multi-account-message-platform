# 项目规则：多账号群组消息平台

## 权威文档
- `docs/examination_project.md` 是完整的本项目要求。本项目是一个招聘全栈程序员的笔试项目，要求48小时完成。一切实现以它为准。
- 每次开始一个任务前，先读一遍相关章节。

## 运行环境
- Qoder 跑在宿主机。
- 整个笔试项目的实现最好采用 docker-compose 一键部署，测试程序/脚本可以使用宿主机的 bash/python 脚本，但是脚本最好只调用容器服务，避免脚本太重。
- 整个笔试项目交付必须是可以通过本项目，然后通过 docker-compose 的一键部署，这样面试官可以快速验证笔试项目是否符合预期。

## 代码修改工作流
1. **强制规划**：对于任何涉及代码修改的请求，你**必须**先进入只读研究模式，输出一份详细的修改计划（包括涉及文件、具体改动点、潜在影响）。
2. **等待确认**：计划输出后，**必须停止**，等待用户输入确切的暗号 `codecode`。
3. **禁止提前行动**：在收到 `codecode` 之前，严禁使用任何编辑工具（Edit, Write, MultiEdit）。
4. **确认后执行**：收到 `codecode` 后，严格按照已展示的计划进行修改。

## 代码质量要求
- **清晰的注释**：避免 hardcode。关键的逻辑必须有详细注释。
- **合理的分层/分文件**：每个代码文件不能超过 50KB。不能有超过 1000 行的代码文件。
- **单次垂直功能**：每次只做一个垂直功能，做完 typecheck，再询问是否需要 commit 以及 commit 的消息内容。
- **类型安全**：不要为了过 typecheck 而用 `any` 或 `@ts-ignore`；实在需要就写 TODO 注释。
- **数据库迁移**：数据库改动一律通过 migration，不要手动 psql 改 schema。
